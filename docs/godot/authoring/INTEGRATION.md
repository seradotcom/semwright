# Godot semantic authoring integration

## Authority and dependencies

D extends the existing first-party Godot driver. It does not define a second Composition kernel, policy engine, artifact transport or project graph. Plans, owners, base states, budgets and verification reports are A contracts. Durable project/file identities, apply receipts and trusted native revision admission consume C through `504ad2c6632305b580b51703a60b0a194865780d`. Effect predicates, collection and evaluation use F. PR #176 is D's development PR; merge to main and R16 closure are outside D authority.

driver.godot.composition.plan is the semantic entry point. It advertises the existing generic artifact input classes, including artifact-in:model/3d. Bytes from Blender or another producer must first cross the Broker generic artifact.handoff into the configured Godot input grant with a pinned digest. D never reads another driver's private output path.

## Product route

The managed loop is inspect -> plan -> apply -> measure -> validate -> optional bounded repair -> verify. A plan is owner/session bound in PlanVault and is not permission by digest. Apply writes only provider-managed files under configured output/state grants. Composition inspect preserves the Store's per-file C LogicalAssetId, AssetRevision, kind, logical key and active state alongside expected/actual hashes, instead of collapsing persistent identity into a path or digest. Behavior transforms remain typed: position/rotation/scale reference typed expression nodes, while reparent accepts only managed logical entities and an explicit keep_global flag; validation rejects self/descendant cycles, incompatible dimensions and nonspatial keep_global targets before code generation. Human drift is DIVERGED and blocks overwrite, native execution and export.

`driver.godot.composition.native.verify` is a combined authoring+runner CodeExecution route. The caller supplies an issued plan_id, managed scene ID and typed inspect/persistence/play scenario. The driver resolves Owner, ProjectId, plan/intent digests and current source fingerprint server-side, requires IN_SYNC, copies verified managed sources to a private directory, runs pinned Godot import and the fixed observer, then evaluates through F. Native result admission is crate-private and trusted results are not deserializable from client JSON. `driver.godot.composition.native.query` reuses the same authenticated inspect/F path but returns only one managed node selected by logical key or one persistent `res://` resource plus at most 32 explicitly requested properties; it does not return the complete observation. `driver.godot.composition.native.tracks.page` and `driver.godot.composition.native.keys.page` likewise reuse authenticated inspect but return only bounded collection pages plus F evaluation. Track cursors bind source fingerprint and normalized native projection; key cursors additionally bind the exact player/library/animation/track selector, so a new process can continue only while the observed content and requested collection are unchanged.

Persistence uses two Godot processes: save candidate then reopen. External dependency sentinels must remain byte-identical. The dedicated godot-persistence lane also reruns the #171 scene-only native contract for external material/texture bytes, shared/embedded subresources and inherited-scene fail-closed behavior. Play accepts only declared InputMap actions, bounded ticks/checkpoints/variables and optional frame digest capture. Native readback preferences remain UNKNOWN when enumeration is incomplete; required source rules remain authoritative for source verification.

Existing project.validate, project.run_test and export routes accept either a paired configured project ID or one logical managed_project, never a path. Managed execution reopens Store, requires IN_SYNC and stages verified bytes. Export excludes authoring manifest/spec/source maps/addons; the dedicated godot-export lane validates/runs the managed project, builds the release package, scans it for authoring-only markers and launches it with a clean HOME and no editor/Semwright process.

## Cross-role handoffs and limits

C consumes D's authenticated apply receipt and retains UNKNOWN frontiers. F native evaluation is returned with native readback but does not become a grant. D12 pins E source `d80471b9ceb828a2a531dfac9eaa4e970ea589a9`, run `36543391358`, artifact `11023505708` and articulated GLB SHA-256 `f756e288afb978993488e2f59b07179b1c97f7801d5f4314166de0d2b6db7ca5`; that E run completed successfully, including native authoring, fresh-Blender GLB oracle, hostile GLB, fuzz, Skill, source backup and formatting. The D12 route runs only after the same native-authoring runner has already attested Driver Host: it first creates and plays the managed 3D game with its baseline triangle GLB, records logical bindings/behavior bytes/collision mapping, revalidates E's receipts, moves articulated.glb through generic `artifact.handoff`, then replans the same logical asset slot and requires those unrelated bindings/behavior/collisions to remain unchanged while skeleton/bones/skin/materials/animation, fresh reopen and gameplay reflect the Blender replacement. `composition.verify` then emits the real admitted C ExecutionReceipt for that replacement apply, and D12 pins the articulated GLB LogicalAssetId/AssetRevision/SHA from its outputs. A dependent cross-app oracle job independently redownloads the pinned E artifact and revalidates the D/C receipts and exact GLB bytes. For read-only native provenance, D now constructs C's versioned `RevisionCandidate` from the authenticated native result and the Store's stable scene `LogicalAssetId`; the projection uses `godot_native_project_observation` v1. D never manufactures C's binding generation: the trusted Project Graph host supplies the current generation and only C `RevisionAdapter::admit` plus `ProjectGraph::accept_revision` can promote the candidate. There is intentionally no public `project.revision.admit` capability, and this observation creates no production activity/receipt.

The branch does not claim arbitrary adoption of non-empty human projects, cross-app transactions, exactly-once native execution, complete rollback, sandbox perfection or Windows/macOS native authoring. Missing native execution, incomplete enumeration or drift remains UNKNOWN/FAIL. Missing-managed-source repair is authorized through the original A budget and lineage; Partial/Unknown publication reconciliation is intentionally not exposed because current C0 and current A head leave PlanVault attempts non-retryable after a non-Completed outcome and provide no reconciliation transition. Store recovery primitives therefore remain internal until A publishes that authority contract.
