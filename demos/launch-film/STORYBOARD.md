# Semwright launch film storyboard

Target: **52 seconds**, 1920×1080, 30 fps, 16:9. The piece is an editorial developer-tool film, not a product-UI simulation.

| Time | Beat | Visual | Claim discipline |
|---|---|---|---|
| 00:00–00:06 | Pixels are a fallback | Sparse coordinate crosshair, terse typography: “Screenshot. Guess. Click. Hope.” | Conceptual illustration only; no fake application UI. |
| 00:06–00:13 | Meaning | Semantic object words become stable chips: window, button, object, scene, clip, cell, timeline. | These are semantic object classes/concepts represented in Semwright’s architecture. |
| 00:13–00:22 | Boundary | Agent → Semwright → Capability Registry → Providers, with a single line of policy/audit/refs/jobs. | Mirrors the repository architecture and avoids claiming a second authority path. |
| 00:22–00:31 | Real providers | Browser, Blender, OBS, MLT, LibreOffice and Motion Canvas orbit Semwright. | Labels are shown only when their first-party integration exists in the frozen baseline/branch. No fake screenshots. |
| 00:31–00:38 | Hierarchy | Native application API → semantic OS accessibility → input fallback → vision last. | Product philosophy, not a benchmark or performance claim. |
| 00:38–00:46 | Self-hosted proof | Semantic model → Motion Canvas → validated frames → MLT final encode. | The final CI build must actually execute these stages before this cut is publishable. |
| 00:46–00:52 | Close | Semwright mark, name, “Semantic computer I/O for agents.”, project URLs. | No invented metric or autonomy claim. |

The source intentionally avoids fake terminal windows, fabricated application screenshots, synthetic benchmark numbers, generic particles and futuristic HUD motifs. If real product footage is later inserted, it must come from an actual Semwright-controlled run and be recorded in `DEMO_TRACE.json`.
