# Godot semantic authoring release impact

D is additive to the existing Godot driver. Existing paired-editor capabilities retain their public names. The branch adds managed Composition authoring, native verification, logical managed-project selection for runner/export routes, a production Skill and development evidence/package tooling.

Managed authoring is opt-in through owner configuration. Without authoring config the eight Composition-plan lifecycle routes are absent. `composition.native.verify`, `composition.native.query`, `composition.native.tracks.page` and `composition.native.keys.page` additionally require a pinned runner and are not exposed with only one side configured. Legacy context-free execution cannot manufacture owner-bound plans, targeted native-query authority or native paging authority.

The typed intent plus provider derivation record are the source of truth for managed content. The profile now models typed AnimationTree state machines/BlendSpace1D graphs and explicit shared versus local-to-scene material bindings; per-file C asset/revision identities remain visible through Composition inspect. Generated Godot files remain editable in normal Godot, but a manual change becomes DIVERGED and blocks automatic overwrite/run/export until an explicit decision and replan.

Initial native acceptance target is Linux with pinned Godot 4.7.2. Portable source contracts do not imply Windows/macOS native production support. Exported games are intended to run without Semwright; editor bridge, native observer and private state are not normal package contents.

The branch consumes A Composition, C Project Graph and F effect-conformance contracts at compatible revisions. Merge does not close R16. GODOT_AUTHORING_READY remains false until exact-SHA model/native/persistence/export/hostile/cross-app gates, the gated package and required cross-role evidence are present.
