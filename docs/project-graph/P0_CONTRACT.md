# Project Graph P0 contract

`crates/project-graph`, this documentation, its diagnostic workflow and the continuity Skill form the Project Graph subsystem. Shared Composition types come from C0 `26602e4b25929be869d69ef28fef4dd9713180d7` rather than a private copy. Compilation/test evidence is attached to the exact diagnostic source SHA; publication alone is not READY.

Public source exports ProjectId, LogicalAssetId, AssetRevision, DerivationId, ReceiptId, DurableLocator, Fingerprint, RevisionPin/Record, RevisionCandidate/RevisionAdapter, OperationIdentity, ExecutionReceipt, ReceiptAdapter, Relation/EdgeEvidence, Coverage and multidimensional Knowledge. Schemas are generated by the `schemas` example. The `p0`/graph tests exercise identity, duplicate/unknown wire fields, portable locator negatives, partial dependencies, exact reversion, digest/projection equivalence and trusted observation admission. These are contract fixtures, not native pipelines.

## Native application integrations
Keep native NodePath/ResourceUID/bpy/datablock extractors in your driver. For read-only/import/readback evidence, return a versioned `RevisionCandidate` rather than fabricating an `ExecutionReceipt`: it carries schema version, existing LogicalAssetId, fingerprint/equivalence, current binding generation, ObservationRef and Coverage but no AssetRevision. The trusted host constructs a registered `RevisionAdapter` for the exact ResourceKey + EvidenceSource + method/version, binds authenticated Owner + ProjectId + current asset/generation, and Project Graph allocates AssetRevision inside the resulting non-deserializable `AdmittedRevision`. `ProjectGraph::accept_revision` records observation only; it creates no activity/producer edge and incomplete coverage remains non-cache-safe. Mutating authoring/export continues to use real input/output pins plus `ReceiptAdapter`. A native resolver is an explicitly registered host integration, not a path/name guess. Report unsupported stable identity as ambiguous/UNKNOWN, not inferred continuity. For Blender→GLB→Godot, each export, handoff, import/readback and verification retains its own evidence; byte equality does not collapse their logical assets.

## Composition / Audio
C0 identities/evidence are consumed now. C1 AV is inspected but not yet linked into Project Graph. Project Graph needs a public fixed-stage receipt adapter for final media artifacts and the published manifest, including exact audio/master/stem and motion inputs, cue/runtime/parameter dependencies and incomplete coverage. The AV layer retains publication pointer ownership. The audio subsystem retains audio analysis and authoring. No private helper calls, copied media clock, extra scheduler or receipt fabricated from a media filename.

## Effect Conformance
Project Graph stores the bounded VerificationReport/effect result over shared Composition types. Required UNKNOWN/FAIL remains visible. Receipt admission is not a quality verdict. Fixture/simulation cannot become native acceptance. Review method/completeness mappings against this P0 before introducing P1 wire changes.

## Authority and version changes
The non-deserializable `AdmittedReceipt` and `AdmittedRevision` are constructed only by trusted registered host adapters after authenticated execution or observation. Never expose either `admit` function or adapter registration as a client capability. `RevisionAdapter` admission is provenance binding, not verification and not a derivation receipt. A matching digest is neither a signature nor a grant. Persisted session identities are historical, not reusable refs. P0 schema version remains 1; the additive `revision_candidate` schema must be validated explicitly before use.

## Current integration blockers
Exact-SHA native Blender evidence and native Godot observation/readback machinery exist, but the recorded combined cross-app Project Graph activity/evidence gate remains open at this checkpoint. Candidate graph-state Broker routes, store, queries and continuity package are implemented and require exact-SHA integration evidence; typed rebuild dispatch and AV integration remain separate obligations. No PROJECT_GRAPH_READY or R16 closure is implied by P0.
