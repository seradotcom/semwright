# Semwright semantic-authoring launch landing

## Purpose

Build a launch-quality Semwright landing concept as native editable Figma structure. The design is evidence-led and editorial; it is not a simulation of a terminal, IDE, or fake application UI.

## Visual direction

- warm ivory and paper surfaces;
- cobalt plus deep ink accents;
- editorial typography with large headlines and restrained supporting text;
- generous negative space;
- thin, deliberate hierarchy rather than card spam;
- real architectural/product claims only;
- no purple-neon AI aesthetic, glowing orbs, fake testimonials, random gradients, bento-grid filler, or decorative terminal clichés.

## Desktop

The desktop profile is 1440 px wide and contains navigation, hero, evidence field, thesis, authority-flow section, verification section, and closing statement.

The hero balances large editorial copy with an evidence panel. The architecture section makes the division of responsibility visible: model judgment on one side, Semwright correctness/authority in the middle, native Figma structure on the other.

## Mobile

The mobile profile is 390 px wide. It is separately authored as a native vertical composition; it does not pretend Figma has CSS runtime responsiveness. It preserves the same narrative while changing hierarchy and order for a narrow frame.

## Claim discipline

Native TextNodes, Auto Layout, revision-bound plans, structured findings, and artifact-backed verification are implementation claims. Visual quality remains a model/human judgment. A verification PNG is evidence, not object identity.

## Convergence fixture

The generated demo intentionally declares a 24 px minimum gap between the desktop heading and body while the initial hero-copy Auto Layout gap is 18 px. This is the real deterministic failure used by the demo runner. The semantic repair restores the declared gap, remeasures, and revalidates.

The A/B/C benchmark normalizes this gap before comparing approaches so the semantic arm is not deliberately handicapped.
